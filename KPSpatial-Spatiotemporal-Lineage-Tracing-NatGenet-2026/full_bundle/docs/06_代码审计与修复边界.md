# 06｜代码审计：确定缺陷、语义风险与尚未确定的影响

审计分成三层：**源代码确实这样写**；**最小输入能否证明该行为不符合某个明确合同**；**终刊结果受影响多少**。前两层可以确认而第三层仍未知。未取得作者最终环境和全部中间文件，因此本章不会把局部缺陷升级成“论文结论全部错误”。

## A. 需要优先重算的统计问题：CNV 一致性 P 值

**文件**：`reproducibility/Figure1/scripts/bootstrap_phylo_infercnv_slidetags.py`。本包保存了完整文件；Git blob 校验与固定提交一致。[C8]

核心条件为 `_score > nn_score`，最终返回 `significance / B`。实际脚本调用 B=1000。它名为 bootstrap，但操作是打乱 CNV 标签的置换检验，不是对细胞有放回抽样。

对上尾检验，若随机置换包含与观测同样极端的并列值，将它们全部排除会得到偏小结果。Monte Carlo 实现通常应计算 `(1 + #{T_perm >= T_obs}) / (B + 1)`，并明确置换群、单／双侧和数值容差；完整枚举则直接计算包含等值的精确尾概率，不能把 Monte Carlo 的 +1 规则机械套入已完整枚举的样本空间。[B3；T1]

本包实际执行了三种合成例子，详见下一章。论文公开结果中纯度为 1 的行会在此实现下机械得到 0，因为不可能有纯度大于 1。**这不证明每一行正确 P 值都不显著；证明的是原“0”不能按当前算法作为可靠的尾概率解释。**[D2]

复核需从原始树和 CNV 标签开始，并核对是否过滤小簇、缺失标签和只有单一标签的肿瘤。检验的零分布必须保留合理的标签数量／比例；将不同肿瘤、动物或不可交换空间区混洗可能回答错误的问题。

## B. 同一 CNV 脚本中的两个额外问题

**缓存未使用**：`assess_nn_purity(..., nn_dict=...)` 仍逐细胞调用 `find_nearest_neighbor`。本包对实际提取函数计数，确认传入缓存后仍重新计算。这首先是性能问题，不改变同一确定邻居定义下的数值。[C8；T1]

**最近邻含义需要澄清**：代码仅在第一个包含其他叶子的祖先子树内找最短距离。对非超度量树，这不保证全树 patristic 最近邻。合成例子中代码选距离 5 的叶子，全树存在距离 3 的另一叶子。如果作者意图是“最近共同祖先子树内的近邻”，它是定义选择；如果意图是全树路径最近邻，则有实现偏差。修复 P 值时不要悄悄更换邻居定义，否则无法区分两个修改的作用。[C8；T1]

## C. Fitness 分组剪枝方向错误

**文件／函数**：`utilities/phylodynamics.py::score_fitness`。

```python
subtree.remove_leaves_and_prune_lineages(
    np.setdiff1d(query_cells, tree.leaves)
)
```

代码前面已经把表达 ID 与树叶取交集；query 通常是 leaves 的子集，此集合差为空。因而“按肿瘤分组”不一定剪掉其他肿瘤。先在整棵树上估计再事后删输出行，不等价于先按肿瘤剪树后估计。[C1；C4]

**建议修复逻辑，未在作者数据执行**：

```python
keep = np.intersect1d(tree.leaves, query_cells)
if len(keep) < 2:
    raise ValueError("Insufficient leaves for this tumor")
subtree = tree.copy()
subtree.remove_leaves_and_prune_lineages(np.setdiff1d(tree.leaves, keep))
assert set(subtree.leaves) == set(keep)
```

原 Figure3 调用节选使用 `grouping_var='tumor_id'` 且启用枝长估计，说明这不是只有名字却未被使用的独立 helper。当前保存的调用证据仍是继承的选段，不是已执行日志；最终归档是否相同未知。[C4]

## D. LBI 名称与实际导出不一致

本次追踪的链条是：KPSpatial `score_fitness` → Cassiopeia `_lbi_jungle.py::estimate_fitness` → vendored `Tree.infer_fitness` → `node_ranking.compute_rankings`。包装层写回的是 mean_fitness，而底层另有 polarizer 分支。[C9–C11]

这个发现要求在论文重建中区分三件事：作者文字称谓、公开软件接口名称、实际数值的生成算法。不能仅以“类叫 LBIJungle”证明导出的是标准 LBI。也不能直接换成另一指标后继续沿用原图注。应先恢复终刊依赖版本，再分别导出候选指标、比较排序、相关性和扩增高低分组；没有这一步，不能定量判断影响。

此外，`fitnesses /= np.max(fitnesses)` 不是一般意义的 min–max 标准化。若分数可为负或最大值接近零，需要显式检查；本包只给出条件性算术反例，未发现作者真实分数的负值证据。

## E. 谱系插补接口直接不匹配

**调用端** `utilities/reconstruct.py::create_character_matrix` 接收两项；**被调端** `utilities/target_site_utilities.py::impute_single_state` 的正常和无票分支均返回三项。触发这条路径时，Python 会报解包错误。[C2–C3；T2]

把接收变量改为三项仅修复接口；还必须决定是否按目标分析要求检查第三项支持数。最小票数、原始／插补供体、允许填入未编辑状态与否、迭代轮数，都是独立的科学合同，不应为了“跑起来”随意选默认值。

## F. 三个过滤问题

**spot 阈值变量混用**：聚合到 cell／spot 的 UMI 却用 `minimum_intbc_umi_support` 比较，`minimum_spot_umi_support` 未按预期控制这一步。**未编辑比例筛选被覆盖**：先用 PercentUncut 得到的 overlapping_cells，随后被另一集合赋值替换。**行过滤变成细胞保留**：先找至少一行达标的 cellBC，再保留该 cellBC 的全部 allele 行，弱支持行可能重新进入。[C2；T1–T2]

这些都是可识别的局部逻辑；上游数据是否已经做过相同过滤、因此真实影响是否有限，仍需要原始输入决定。修复时应分别命名 spot 总 UMI、intBC 支持和 intBC–allele 行支持，不要用一个泛化阈值覆盖三种单位。

## G. 文件接口与参数边界

`score_neighborhood_abundances.py` 出现没有插值的 `{HOMEDIR}` 字面路径；共识打分生产者用空格写同名 `.tsv`，消费者却用制表符读取。存在未公开的人工转码可解释实际文件为何可读，但不能把这种可能当作已经发生的事实。[C5–C6]

共识基因的四分之一门槛是严格／非严格边界差异。半径代码中的 `RADIUS=28` 未核实坐标单位，不能自动等同于 28 μm，也不能默认与方法 30 μm 无差别。通用重建入口的默认 500 与方法 1000、默认一致性 0.7 与某些 benchmark 的 0.8，可能被调用参数覆盖，不属于已证明的终刊执行错误。[C2；C5–C6；P2–P3]

## H. 修复优先级

[H] 首先恢复最终文件与依赖版本，保持只读快照。然后修复确定的接口、路径、集合和 P 值缺陷，输出逐细胞／逐字符差异账本。最后才调整最近邻定义、空间零模型、组成控制或新的稳健性方法，因为这些改变分析问题本身。所有新方法输出与作者原结果并排，禁止覆盖原始文件后丢失反事实对照。

本包提供的是独立的 `tools/permutation_nn.py`，只接受已确定的固定邻居图和标签，包含输入验证、含等值上尾、随机种子、可选分块和退化零分布标记；不是声称已经修复整个作者仓库的 patch。
