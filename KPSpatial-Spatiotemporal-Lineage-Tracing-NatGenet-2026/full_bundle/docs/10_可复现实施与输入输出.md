# 10｜怎样把准备包推进为真正可复现的分析

## 先明确本包不包含什么

本包不包含终刊完整 PDF、补充 XLSX 全表、完整 KPSpatial／Cassiopeia 仓库、6.1 GB 处理后数据或原始 FASTQ。现在可重跑的是局部审计。作者分析需要的完整依赖版本、数据输入、随机种子、实际命令和图生成输出，尚未形成闭环。[P1；Z1–Z2；R1–R2]

## 第一道门：固定源与实验单位

[H] 从文章列出的来源取得合法可访问的原件后，先列文件、大小、哈希与许可证，不立即加载 pickle。将 Zenodo 代码归档与 GitHub 两个提交做目录及内容 diff，尤其比较 CNV P 值脚本、插补接口、fitness 分组与 LBI 包装层。逐个分析绑定代码版本，而不是只给整个项目写一个“latest”。

[H] 建立样本设计表：animal／patient、tumor、section、array、library、platform、stage、site、sex、batch、treatment。每个图的统计 n 从该表生成。PBMA 的数量矛盾要在这一步解决，不能留到作图时改图注。

## 第二道门：检查可计算对象

|对象|本包建议的最低合同|失败时应停止什么|
|---|---|---|
|表达 AnnData|全局唯一 ID、gene namespace、counts 与 X/raw/layers 语义、坐标单位、平台和样本字段|表达打分、DE 与空间图构造|
|allele table|cellBC、intBC、UMI、readCount、位点状态；聚合单位明确|字符矩阵与树|
|character matrix|缺失、未编辑、混合状态定义；state↔indel、priors；是否插补|所有谱系统计|
|树|叶子 ID 与输入一致、根与枝长单位、求解器和零编辑边策略|fitness、plasticity、近邻一致性|
|社区集合|发现样本、模块成员、共识阈值、基因覆盖、控制基因|社区评分及跨样本比较|
|CNV 标签|每细胞标签、未分组标记、小簇策略、参考细胞|ED3 置换检验|
|空间邻域|图规则、半径／K、坐标单位、截断和跨切片限制|邻域富集、空间 DE 与 LR|
|输出表|索引唯一、行／列语义、分隔符、父文件哈希|下游合并和图生成|

这些是本包提出的合同，不是声称作者原包已有相同字段或文件名。

## 按依赖图分批运行，而不是一口气运行全部 notebooks

[H] **批次一：无科学推断的完整性检查。** 统计 ID、单位、缺失、负值、归一化语义和环境导入；CNV helper 先用本包合成 fixture 验证。**批次二：恢复一个最小真实样本。** 分平台验证字符矩阵、树和 score；保留原版与修正版输出。**批次三：每个动物／肿瘤的完整支路。** 测量修复造成的细胞保留、树拓扑、fitness 排序、阈值分组和社区关联变化。**批次四：再生成全队列统计与图。**

[H] 输出差异不能只给两张图。需要：保留／删除 ID 交集，受影响字符数，树分裂一致性，fitness 排序相关与负值比例，高低组标签改变比例，CNV 原／修正 P 值和 FDR，DE 效应与显著集重叠，以及转移相关区域的阈值敏感性。

## 修复轨与方法改进轨分离

[H] 修复轨尽量只改确定错误：解包、变量、剪枝、路径和置换包含等值。方法改进轨另做全树 patristic 最近邻、空间限制零模型、不同插补方法、不同社区特征和分层模型。二者输出分开，不能把多处改动混在一次跑分里，然后把变化全部归因于某个 bug。

## 环境不是随意拼版本号

[P/C] 补充方法与 Reporting Summary 对 Scanpy 给出不同版本；分支还涉及 Cassiopeia、ILP／Gurobi、快速 NJ 以及特定降维／空间工具。[P2–P3；R1–R2]

[H] 保留作者环境与审核环境两份锁，不使用一份猜测依赖列表冒充精确复现环境。先依据真实调用决定是否需要 GPU、ILP 求解器和哪些额外库；记录已测的内存／时间，不能预填未经运行的硬件需求或声称几个小时可完成。

## 原工作流的形式状态

原重建流程严格区分“已执行验证”“材料完整但未执行”“受阻”“材料冲突”。本包没有任何论文分析被标记为已执行验证；实际局部函数测试放在独立 audit 收据中。原工作流的 source→analysis→output 核验仍受全文、原始输入和完整仓库缺失限制。结构验证通过，只说明引用、状态和文件组织满足该合同，不授予科学结论认证。
