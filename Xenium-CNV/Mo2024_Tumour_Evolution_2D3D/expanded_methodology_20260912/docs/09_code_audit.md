## 3. 最需要克制的归因：不要把发现一个函数问题扩大到整篇论文

【C】C06 同时计算 jac、jac_pred、jac_all；末端选中的是 jac_pred。无概率函数的不对称性是明确发现，但它不是最后选中的矩阵定义。不能写成“论文所有克隆都是由不对称矩阵生成”。

【C/P】同文件还遍历候选 K，而论文报告树高比例切分和人工检查。当前只能说公开候选脚本与最终方法不完全一致。要确定实际影响，必须获得最终相似度矩阵、选中分支、手工修改以及产生最终图的脚本。

【I】类似地，Mushroom损失输入存在语义差异，并不直接告诉我们最终邻域错误了多少。修正后的模型可能改变梯度、训练动力学和结果；需要受控比较，不能只根据数学不等价断言整体失效。

## 4. 为什么有些看起来像错误的地方不应列为错误？

【C/I】通信对象在HVG选择前复制，因此不是“只对HVG算通信”；`adata_dis500`的名字不证明阈值是500；默认(8,4,2)是层级分支而不是累计邻域数；空cases说明快照需配置，不证明作者没训练；新版Morph功能多不证明它就是原文版本；当前DeepCell访问要求也不能倒推2024年相同。

合格审计不仅找问题，也应删除错误指控。每个问题都应写清触发条件、已读调用链和实际结果是否检查。

## 5. 论文参数、代码字面量、默认值与运行值

[参数表](../tables/parameter_provenance.tsv) 使用如下来源类别：

- `reported`：论文声明。
- `implemented_literal`：指定快照活动语句中的字面量。
- `implemented_default`：CLI、类或库默认配置，可被覆盖。
- `implemented_snapshot`：某次公开文件的状态，例如空列表。
- `unresolved`：当前材料不能确认。
- `own_test`：本档案原创测试的设置。

本档案没有 `observed_author_runtime` 参数。即使Methods和默认值恰好相同，也不把全部运行配置自动视为已闭合。

## 6. 代码级修复与科学级替代必须分开

【H】消除输出路径覆盖、缓存身份缺失、隐式矩阵assay属于提高可观察性与安全性的工程工作；改变参考、相似度、距离、聚类方法、损失函数或边界宽度则会改变科学分析。

建议记录三条分支：`original_snapshot`保存原始输入与代码；`execution_adapter`仅解决明确路径和接口；`sensitivity_or_corrected_model`记录改变科学定义的候选。每条分支绑定输入hash、版本、argv、输出目录和结果。不能混在一个“修复后复现”标签下。

原创 NumPy 合成检查共24项，输入均为手工定义的数学例子。通过仅说明这些具体检查符合预期性质或重现反例，不说明论文公式对真实生物学是最优，也不说明作者代码已运行。

验证记录保留源代码 SHA-256、Python/NumPy版本、测试数、错误和日志；具体见[测试说明](../code/README.md)。全部患者数据流程、空间统计稳健性和模型消融仍未执行。
