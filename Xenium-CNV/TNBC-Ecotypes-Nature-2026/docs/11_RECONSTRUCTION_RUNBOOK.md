# 11｜恢复执行路线：什么可以核查，什么必须先补材料

[返回](../README.md) · [25张方法卡](../protocol/25_ANALYSIS_CARDS.md) · [参数台账](../sources/PARAMETERS.tsv)。这是执行合同与顺序，不是已经跑通的生物分析管线。

## 1. 先区分三种完成

**材料整理完成**：研究故事、图与方法映射、源码定位、参数来源、竞争解释与阻断点已记录。

**代码局部检查完成**：某个脚本或函数的静态行为被审读，合成输入的数学定义经过测试。这不保证其全部依赖、历史输入与实际发表结果绑定。

**经验复现完成**：在明确版本、真实输入和环境中运行，并与作者目标输出按预定标准对比。本项目尚未完成这一层；patient／animal analysis runs均为0。

工作流依据是用户指定的 `reconstruct-bioinfo-protocol-pr630-4bdc4d0.zip` 中的证据合同思路。本文档不把“生成了manifest”或“脚本正常退出”写成生物学复现成功。

## 2. 先获取能改变判断的最小对象

优先拿到患者临床表、细胞metadata、最终恶性判定列、癌细胞pseudobulk、患者×状态频率、最终ecotype邻接／成员、Xenium坐标／标签／niche、预测模型分割／系数。只有这些对象之间的差异需要追溯时，再按模块获取原始FASTQ、完整图像和转录本。

这些“优先”不表示对象已下载或始终公开。访问入口和历史读取状态见来源表；以当前实际收到的文件及权限为准。用户未要求联系作者，不自行发送邮件；也不上传临床数据到代码仓库。

## 3. 最低目录与输入合同

建议在独立工作目录使用 `inputs/`、`runs/source_exact/`、`runs/methods_declared/`、`runs/adapted/`、`results/`。本idea目录不预填伪造的作者RDS或空模型。

每个输入至少记录来源、大小、SHA-256、样本ID、行列方向、基因ID、物种、assay／变换、单位与时间。counts需要非负整数，坐标需要说明μm／像素；不能把整合后的负值矩阵送入要求原始计数的模块。

按样本空间命名cell ID，避免不同Xenium样本条码相同被误判同细胞。一个样本必须映射到唯一动物／患者和取样时点；一个动物出现多个时点可能合理，但必须明确重复测量设计。

## 4. 三条分支不要互相覆盖

`source_exact`：冻结作者源码及实际输入，尽量恢复原路径。缺失helper或人工对象就停止并记录，不用新工具偷偷替代。

`methods_declared`：当论文文字与当前代码不同，按正文可确认的声明重建比较分支。它不是原代码，必须单独标记。

`adapted`：纠错或迁移方案，包括无泄漏评估、独立单位修订、空间敏感性。不能将它的新结果宣称为作者当时做过的分析。

三个分支共享不可变原始输入，但有独立缓存、日志和输出。缓存键至少绑定输入、代码、参数和关键环境。手工判断写入日志及细胞／程序ID，不能只改内存对象后保存覆盖文件。

## 5. 第一阶段：元数据与定义核查

运行 [audit_inputs.py](../code/audit_inputs.py) 检查所声明的CSV合同，确认ID、父谱系和分母。该工具不检验标签真值、区域面积、临床结局、批次可分离性和原始counts分布，这些需按数据类型补独立检查。

输出每个分析的纳入清单，特别处理无谱系、无结局、治疗转轨、未知状态和缺少平台。论文39／46匹配病例、检验名称等差异在没有对象证据前保持未仲裁。

验收不是“所有NA已填掉”，而是每个NA都有语义，所有分母可解释。只要出现ID错配、错误单位、未说明矩阵变换，暂停后续统计。

## 6. 第二阶段：优先重跑会向下游传播的关卡

### 6.1 身份判定

选一个参考充足、癌细胞marker清楚的患者，保留CNA矩阵及所有判定列。在固定输入上比较Methods与code阈值；报告每个细胞切换方向和独立身份支持，而不只给总准确率。没有真值时不能把两方法一致当准确。

### 6.2 Pseudobulk与NMF

核对原始聚合、VST、实际基因列表和缓存。比较筛选分支的基因交集、因子匹配与患者软负载。检查rank、正则、归一化尺度和并列值；冷缓存与热缓存必须指向相同已声明输入。

### 6.3 MP与细状态

恢复逐患者因子→QC→Jaccard→合并→marker链，记录每轮人工选择。按独立患者支持率评价重复程序，不能用多rank当多患者。评分、二值、多标签和dominant label分别保留。

### 6.4 Ecotype

在同一个患者频率矩阵上比较不同筛边规则；输出每条边的有效N、rho、p/q、所用样本和共分配。固定图算法重复与患者重抽样分开。对RCOP手算几组值检验定义，别把边宽当相关系数。

## 7. 第三阶段：一个样本的空间闭环

获得一个示例的细胞边界、坐标、转录本／表达、状态、H&E配准和niche结果。先手算少量邻域检查中心是否计入、半径端点、跨ROI和unknown分母，再核对全样本组成。

标签验证要有marker覆盖、投票与失败标签；基因留出一致不是患者外推。对代表ROI核查来源，但最终支持率必须回到全患者，不只选择最清楚的窗口。

确认样本内niche→跨样本meta-niche映射，以及每患者贡献、组织边界和密度敏感性。没有完整step1／helper不自动补常规空间规则。只有单样本定义正确，才考虑全44位Xenium患者的计算。

## 8. 第四阶段：预测和外部映射

首先恢复真实split IDs、候选生成、填补对象和预测概率，再重跑作者路径。另建无泄漏分支，以相同外层患者划分比较基础与扩展模型。若使用全数据发现的状态，需明确是描述性图谱还是部署评估，并处理对应信息边界。

外部基因模型缺少有序基因／截距／系数／变换时不执行假预测。外部archetype合并再NMF属于队列依赖映射，不能改成冻结投射后称“完全复现”。将batch预测、single-sample部署、预后关联和治疗获益主张分开。

## 9. 预先规定的验收量

| 模块 | 应验收的对象 | 不能当作成功的替代物 |
|---|---|---|
| 身份 | 细胞ID、最终判定列、切换表和来源依据 | 一张相似UMAP |
| NMF | 输入哈希、W/H及匹配、患者负载 | 仍能分成四组 |
| MP | 各轮成员、marker、患者支持 | 得到13个功能名字 |
| 状态频率 | 正确分母、NA、纳入个体、效应量 | 只有P值 |
| 网络 | 边、有效N、过滤、共识、布局分离 | 网络图看起来紧密 |
| 空间 | 几何定义、标签不确定性、患者支持率 | 一张漂亮ROI |
| 预测 | 留出信息边界、逐患者概率、区间／校准 | 脚本返回一个较高AUC |

误差容许范围应在看到结果前根据对象精度预定。本次没有作者完整目标数值，不能填写虚构expected outputs或“通过阈值”。

## 10. 环境与成本

作者模块横跨R、Seurat、RcppML、CopyKAT、CellChat等；文中版本与真实session仍应绑定。历史注释不等于实际安装版本。锁定复现环境可以保护原路线；迁移环境应独立记录，不强求把旧版本作为永远通用方案。

先profile单样本的peak memory、wall time、稠密转换和anchor规模，再决定分批策略。没有全量运行，不给虚假的精确GPU／内存／耗时。增大序列化上限不等于分配了内存，GPU也不自动加速所有R对象处理。
