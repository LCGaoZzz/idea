# 04｜八条见解：从论文经验到可证伪的研究问题

[上一章](03_methods.md) · [目录](../README.md) · [下一章](05_research_proposal.md)

以下每节先给**论文依据**，再给**推论**与**验证设计**。后两者是本 idea 的分析，不自动成为作者已经证明的结论。来源编号见 [SOURCES](../evidence/SOURCES.md)。

## 见解一：有价值的闭环不是「反复调用」，而是更新问题的条件

### 论文依据

NISE 将联合预测得到的新骨架与配体坐标重新送入序列设计器。exatecan 设计中出现局部螺旋重塑、螺旋间距变化和配体向内移动。固定原始骨架上的序列重复采样无法自然产生相同的条件更新。[S1 Fig. 1、Fig. 3]

### 深层解释

一次性串联的隐含假设是：上游结构已经足够正确，下游只要找到与它兼容的序列。但困难任务的误差通常同时位于序列和条件几何。闭环把条件本身变成优化变量，因而可以跨出原骨架所定义的局部解空间。

这与简单地「把最优序列再喂给模型」不同。真正应跟踪的是每一代的父状态、输入结构、生成序列、预测结构和选择理由。否则，即使跑了很多轮，也不能判断收益来自新几何、更多抽样还是单纯挑选极端值。

### 可检验的新问题

在相同联合预测调用预算下比较：固定输入骨架反复采样；允许重新预测但不反馈更新坐标；完整反馈更新。三者都采用同一最终独立评估。若完整闭环只改善内部 pLDDT、不改善独立指标或实验命中，说明增益可能来自适应评分器而不是找到更真实的结合解。

进一步可拆分「仅反馈蛋白骨架」「仅反馈配体坐标」「两者同时反馈」。但交换坐标前必须检查相互碰撞、原子映射和坐标系，不能生成物理不可能的中间输入来构造不公平消融。

### 对代码和工程的含义

记录谱系比记录一个最终最高分更重要。不要重新开发大型工作流引擎；复用既有执行系统，补齐每轮输入输出与选择表即可。`screen.py` 给出可审计的筛选结果，完整闭环由上游 NISE 执行，不在轻量分析代码里伪装生成模型。

## 见解二：几何约束应先于置信度，且必须保护坐标系语义

### 论文依据

作者发现很多序列的骨架预测是自洽的，但配体方向并不正确；即使质心接近预期，也可能没有正确识别。NISE 同时约束蛋白与配体一致性。[S1 exatecan 设计段]

### 深层解释

整体折叠、结合位点位置、配体内部构象和配体相对蛋白的方向是不同问题。一个低配体 RMSD 可以来自真正自洽，也可以来自错误的独立对齐、错误原子映射或把容易失败的官能团从计算中排除。

因此，方法可信度不取决于是否调用了一个叫 RMSD 的函数，而取决于这个函数测量的对象是否与科学问题一致。相同数值、不同对齐范围，不能共享一个阈值。

### 可检验的新问题

构造几何负对照：保留配体内部构象但平移到另一口袋；保持质心但旋转取向；交换不等价原子；镜像改变手性。检查筛选器是否能拒绝这些假阳性。若只能通过真实蛋白但不能拒绝明显错误结构，筛选器未被充分验证。

### 代码对应

`geometry.py` 在蛋白对齐之后，将相同刚体变换施加于配体。测试包括「整体共同旋转平移后 RMSD 接近零」和「只移动配体时误差保留」。化学等价映射必须由可信的分子图匹配提供；本代码验证排列合法性，但不假装仅凭坐标证明化学或手性合法。

## 见解三：可设计性本身是搜索资源，不应只追求骨架新颖

### 论文依据

作者先建立可由多条序列编码的高置信骨架集合，再围绕少量药物放置姿势优化。论文讨论中也强调预计算的高可设计性骨架具有计算效率优势。[S1 scaffold 设计与 Discussion]

### 深层解释

一个新颖但难以被序列稳定编码的骨架，会把大量预算消耗在修复折叠上；一个具有足够可设计性的骨架，才允许序列同时满足折叠与结合。可设计性不是美学分数，而是条件空间是否允许多种可行解决方案。

这提示一个资源分配问题：与其一开始对所有姿势同等深挖，不如先用有限预算估计折叠可行性、配体自洽性和化学约束通过率，再对有潜力的区域扩张。该策略应保留探索份额，否则可能只强化预测器熟悉的拓扑。

### 可检验的新问题

比较同预算的均匀分配与自适应分配。评估单位是独立起始姿势或骨架，而不是生成的每一条序列。终点至少包括送检命中率、独立几何质量、几何多样性与每个成功候选所消耗的预测调用数。

若自适应策略提高均值，却使新颖拓扑与化学类别的失败率大幅增加，则不能只宣布效率提升；它可能只是缩小了可解决问题的范围。

### 实施原则

采用两阶段预算合同：固定预筛预算，加上预注册的追加规则。不要以是否已知实验成功来决定追加计算，否则设计收益与实验反馈泄漏混在一起。

## 见解四：局部 proofreading 是完整上下文下的反事实检查

### 论文依据

作者在 Amber-relaxed 的预测模型上固定其余序列，重新检查结合位点残基。Q51N、M97L 的实验改善与 G104M 的减弱提供了方向性证据。[S1 Fig. 4 及 proofreading 段；S4]

### 深层解释

自回归生成和 fully conditional 校对不是同一个问题。前者问「已经生成这些位置时，下一个位置适合什么」；后者问「最终其他位置都确定后，当前位点还合理吗」。这种差异使同一个模型可以在生成结束后发现局部改进，并不自相矛盾。

然而，holo 条件下概率更高，可能反映整体折叠更稳定，而非更有利于特定配体结合。G104M 的讨论提醒我们：未结合状态必须进入解释。

### 待验证扩展

对同一候选分别计算 holo、apo 和 off-target 条件的概率改变，构造局部对比指标；再对多个合理构象、解码顺序与 dropout 重复观察排序稳定性。若某突变只在一个恰好有利的构象中显得突出，应把它列为不稳定候选，而非模型高置信结论。

这不是计算热力学循环。不同状态的构象、溶剂和熵没有被充分积分；对比概率仍是模型启发式指标。真正的结合自由能改变需要实验 Kd 或适当物理计算。

### 验证和证伪

在同一骨架内，比较原始全序列重设计、holo-only proofreading、holo–apo 对比与含 off-target 对比的候选。送检前固定候选数和排除规则；纳入预测有害与中性候选。若 holo–apo 分数不能优于 holo-only 区分结合改善，则不能继续把这种对比视为已有效的特异性校正。

### 代码对应

`binding.py` 提供 `proofreading_delta`，输出 holo 改善与 holo–apo 对比，但字段名称中保留 heuristic，不输出伪造的 ΔΔG。任何概率为零或超出范围的输入都会被拒绝，不以任意 epsilon 偷偷决定结果。

## 见解五：代理指标可以被优化得很好，却没有改善真实目标

### 论文依据

作者观察到 APEX 已验证结合者中 P(bind) 不随相对亲和力变化；其目标/非目标辨别价值与定量亲和力价值不同。NISE 对最终候选还使用相互作用质量和多样性筛选，而非只取最高置信度。[S1 Fig. 6、Extended Data Fig. 7]

### 深层解释

优化器可以探索到评分器的薄弱区。迭代越多、候选越多，极端高分越可能受到选择偏差影响。如果优化与最终验证使用同一个模型、相同输入处理和同一阈值，重复计算不构成独立证据。

因此，闭环系统应把「选择器」与「裁判」区分。第二个预测器并非完全独立，因为模型可能共享结构数据库；但它至少能暴露一部分架构和输出偏差。真正独立的终点仍包括物理实验。

### 待验证扩展

保留一个不参与迭代的评估器，比较每轮内部目标与独立指标的同步程度。记录二者不一致的候选，而不是自动删除。对照配体、错误姿势与扰动输入可检测评分是否依赖预期化学。

可以预先定义：一旦内部目标持续上升而独立指标停滞或下降，就停止进一步强化该轨迹，并调查输入或评分问题。这条规则是否提高实验效率需要验证；不能靠演示模拟宣布成功。

### 避免新误区

把十个高度相关指标加权相加，不会自动获得十份独立证据。Pareto 前沿也不等于实验有效。应先明确每个指标的单位、方向、依赖性和适用任务，再考虑多目标排序。

## 见解六：强结合、化学保护与有效释放是不同优化目标

### 论文依据

EPIC 双突变体不仅更强结合 exatecan，还在所测缓冲液条件下保护其内酯形式；HSA 结合并未提供相同保护。[S1 Fig. 5]

### 深层解释

平衡 Kd 主要约束占据关系，而功能还受结合口袋中的反应环境、驻留时间和释放影响。相同 Kd 可以对应不同 kon 与 koff；即便近似满足 Kd = koff / kon，也不能只由 Kd 判断保护持续时间或释放速率。

蛋白可能因为包埋关键基团而改变水解，也可能因为维持高占据率而保护。在需要释放的递送场景，过慢的解离还可能成为缺点。因此，「把 Kd 压到最低」并不是所有功能目标的正确终点。

### 可检验的新问题

比较一组亲和力相近但口袋暴露、极性环境不同的变体，检查保护效应是否仍不同；或者在不同占据率下比较保护，区分占据效应与结合态化学环境。再使用独立动力学测量约束 kon / koff，而不是从平衡曲线臆测。

这些是机制区分与后续功能研究，不是本目录已完成实验。不能因为某组吸收差谱变化很小，就宣称证明了体内药代或安全性。

### 分析对应

`binding.py` 的质量守恒函数可以估计给定浓度条件下的平衡结合比例。光谱两状态模型的假设和不适用情形见第 7 章；本目录不生成伪原始光谱，也不把 synthetic 曲线写成论文图 5 复算。

## 见解七：命中率分母、谱系相关性与留出设计决定泛化结论

### 论文依据

作者送检候选经过大量计算筛选；apixaban 六条序列来自四个姿势。streptavidin 的 10,000 条序列也共享少量组装体与结构背景。[S1]

### 深层解释

当多个序列来自相同姿势与预测器时，它们共享成功机会和失败原因。按序列数当作独立 n，会使置信区间过窄。只报告筛选后成功率，还会掩盖前端生成成本。

正确的泛化至少需要沿三个轴留出：蛋白拓扑、配体化学家族、起始姿势。蛋白序列不相似不意味着配体口袋信息未泄漏；换药物也不意味着其近邻化学完全未见。

### 可检验的新问题

预先定义跨骨架、跨配体和跨拓扑层级的评估；每层保留完整漏斗：输入姿势 → 生成 → 预测成功 → 自洽 → 最终送检 → 表达/单体 → 结合 → 功能。失败也应进入结算。

报告每一层的分母与条件成功率，并在可行时给出骨架/姿势层级的不确定性。开发阶段的最好结果与预注册外部验证结果分开。

### 数学提醒

即使暂时忽略相关性，4/4 的普通二项比例区间也不会下限为 100%。第 7 章用 Wilson 区间作描述性示例，并明确小样本和嵌套结构使其不能作为全域可靠性证明。

## 见解八：把科学语义做厚，把执行入口做薄

### 源码依据

固定 NISE 版本中，debug 可以放松科学过滤；字段 `rosetta_paths` 在一条路径中实际保存 Boltz 输出；源码示例的 NLL 使用 log10，pLDDT 经过 /100；Python、Torch、Boltz 及子模块有各自版本状态。[S2,S3,S5]

### 深层解释

自动化最容易失败的不是少了一段提示词，而是一个字段或状态被赋予错误语义。运行成功、文件存在、几何通过、实验成立是四件事。一个「成功」布尔变量无法准确表达它们。

Agent 应说明任务边界、输入合同与输出解释，详细方法按需加载。执行系统负责已有的工具调用、会话、权限和产物管理；科学代码负责计算与校验。不要在每个 skill 中另造恢复引擎，也不要允许 agent 用自然语言把未知参数补成论文值。

### 低风险落地顺序

先增加结果表中的单位、来源、alignment_scope、data_origin、debug、mapping_valid 与候选谱系；再增加失败原因和输入哈希；最后才考虑更复杂的搜索调度。前两步不改变科学算法，却能减少错误解释。

本目录代码恰好承担这类有限工作：不启动收费任务，不偷偷下载权重，不运行第三方不可信 pickle，不冒充完整设计器。它可以成为既有执行系统的分析组件。

## 小结：一条统一主线

八条见解最终收敛为同一个问题：**如何让一个会自我强化的设计闭环，始终受到与真实任务相关、语义正确且尽可能独立的证据约束？**
